# Mesh to ZTL — независимый Python-плагин для ZBrush 2027+

Папку можно скопировать целиком в любое место. Blender, установленный аддон и внешние Python-пакеты для работы не нужны.

## Запуск внутри ZBrush

1. Сохраните текущий Tool: конвертер переключает активный инструмент при импорте.
2. В ZBrush откройте **ZScript → Python Scripting → Load** и выберите `MeshToZTL.py` из этой папки.
3. Откройте **ZPlugin → Mesh to ZTL**.
4. Нажмите **Choose Folder**: откроется отдельное окно Windows с полем пути. Можно ввести путь к `!ZBrush\Mesh`, к родительской папке `!ZBrush` или к `job.json`.
5. **Browse...** открывает системный выбор папки; **Paste (replace)** заменяет весь путь текстом из буфера; **Clear path** очищает поле. **Apply / Check** проверяет папку, сохраняет выбор и показывает число готовых, существующих и ожидающих мешей в статусе этого же окна.
6. Выберите режим и опцию перезаписи в окне, затем нажмите **Start / Resume**. Статус показывает текущий меш, результат и путь к журналу. **Stop after mesh** останавливает очередь после текущего меша. **Close** и крестик закрывают окно; во время обработки они сначала запрашивают остановку после текущего меша. После остановки окно можно закрыть.
7. В панели ZPlugin также остаются **Convert Next** (один меш) и **Convert All - Resume** (вся очередь). Опция перезаписи в окне независима от переключателя панели и изначально получает его значение.

После перезапуска ZBrush повторно загрузите `MeshToZTL.py`. Последняя папка и режим сохраняются в `%LOCALAPPDATA%\MeshToZTL\settings.json`. Автоматическая установка в системные папки ZBrush не выполняется.

## Результат и продолжение

- При наличии `job.json` используются его пути и данные уровней. Обычно результат — `!ZBrush\ZTL\Generated.N.ztl`.
- Без `job.json` сканируются OBJ вида `Mesh\<имя>\<имя>_L0.obj`, `_L1.obj`, …; пропуски уровней считаются ошибкой. Подсчёт геометрии больших OBJ может занять время.
- Каждый успешно записанный ZTL отмечается в `standalone_state.json`. При повторном запуске проверяются описание ассета, режим сборки, размеры/время изменения OBJ и ZTL. Это проверка файловых метаданных, не проверка содержимого ZTL через повторное открытие.
- Уже существующий ZTL без актуальной отметки плагина пропускается как **existing (unverified)**. Для его замены включите **Overwrite existing**. Проверенные завершённые элементы всё равно пропускаются.
- При перезаписи предыдущий ZTL временно сохраняется как `.ztl.standalone-backup` и восстанавливается при ошибке. После аварийного завершения с оставшимся backup плагин требует сначала восстановить/убрать этот файл вручную.
- Ошибки и прогресс: `standalone_log.txt`, `standalone_last_run.json`, `standalone_state.json` рядом с `Mesh`.
- Файлы Blender `job_result.json`, `job_log.txt`, `job_control.json` не изменяются; исходные OBJ и коллекции Blender не удаляются.
- Не запускайте одновременно экспорт Blender и этот плагин для одной папки.

**Cycle Build Mode** переключает `AUTO → RECONSTRUCT → PROJECT`. Текущий режим виден через Status. Auto сначала восстанавливает нижние уровни из верхнего; при несовпадении числа граней использует Divide + Project All. Режимы унаследованы от Blender-экспорта: восстановленные нижние уровни и проекция могут отличаться от исходной геометрии. Сохранение UV/полигрупп зависит от исходного OBJ и операций ZBrush.

ZBrush остаётся открытым после конвертации. Окно работает в отдельном потоке Windows, не имеет владельца ZBrush и не блокирует его своим циклом сообщений. Команды конвертации передаются диспетчеру в исходном потоке ZBrush; из потока окна ZBrush API не вызывается. Тяжёлая команда ZBrush всё ещё может занимать его основной поток. Если нативная команда удерживает Python GIL, обновление окна и watchdog тоже могут задержаться. Диалоги ZBrush могут требовать подтверждения. Остановка действует на границе мешей; продолжение запускается кнопкой Start / Resume. Пока конвертация идёт, не редактируйте активный Tool: очередь переключает его.

## Диагностика зависаний

Кнопка **Open Logs Folder** открывает папку журнала. В папке экспорта записываются:

- `standalone_commands.log`: время, процесс/поток, текущий ассет; `BEGIN` перед каждой командой ZBrush с принудительной записью на диск; `END` с длительностью или `ERROR` с traceback. Последний `BEGIN` без `END` показывает незавершённую команду. Не является доказательством причины зависания.
- Watchdog каждые 15 секунд пишет `WAIT`, пока команда не вернулась. После минуты пишет Python-стеки в `standalone_stacks.log`. Нативный код ZBrush в этих стеках не виден.
- `standalone_log.txt`: итоговые сообщения движка; `standalone_last_run.json` и `standalone_state.json`: результаты и продолжение.
- При ошибке создания независимого окна `standalone_ui_error.log` сохраняется рядом с файлами плагина.

При сбое сначала проверьте хвост `standalone_commands.log`. В режиме AUTO после неудачного Reconstruct начинается PROJECT; Project All значительно медленнее. Для диагностики можно выбрать RECONSTRUCT, чтобы отключить автоматический переход к проекции. Плагин не прерывает зависшую нативную команду принудительно.

## Файлы

- `MeshToZTL.py` — интерфейс, запускаемый пользователем внутри ZBrush.
- `converter.py` — загрузка экспорта, проверка путей, очередь, продолжение и безопасная перезапись.
- `folder_window.py` — окно Windows с выбором папки, буфером обмена, кнопками запуска/остановки и статусом. Использует встроенный ctypes, без Tkinter, Qt и дополнительных установок.
- `zbrush_job.py` — отдельная копия `core/zbrush_job.py` из родительского проекта; импортируется как библиотека. Сам файл отдельно запускать не нужно: его исходная точка входа предназначена для Blender-заданий.
- `test_converter.py` — проверки очереди с имитацией сборки ZTL, без запуска ZBrush.

API интерфейса: https://developers.maxon.net/docs/zbrush/py/2026_1_0/api/zbr_cmds_gui.html ; сигнатуры также сверены с Python API установленного ZBrush 2027.
